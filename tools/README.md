# tools

Nothing in here goes into MS Project except the two `.bas` files under
`probe/`, and those are only for answering questions about a real Project
install. **The files you paste into Project are the six in `paste/`.**

## check_vba.py

Run it after every change. It catches the compile errors VBA only reports once
you're standing in front of it: LF line endings, reserved words used as
identifiers, declarations after procedures, unbalanced blocks, invented `pj*`
constants, assignment to a function call, `Private` called across modules,
module names colliding with procedure names, stale form markers, and `paste/`
drifting out of step with the source.

```
python3 tools/check_vba.py
```

## The MS Project type model

It isn't here. It lives in the VBAlidator fork, with the code that builds it:

    vendor/VBAlidator/src/models/project.json      the model
    vendor/VBAlidator/tools/build_project_model.py rebuilds it
    vendor/VBAlidator/tools/extract_project_docs.py  re-extracts the inputs
    vendor/VBAlidator/tools/data/                  the extracted inputs

That's where `--host project` reads it from, and where it can be contributed
upstream. A copy here would only be a second thing to drift.

```
git submodule update --init            # first time
vbalidator . --host project            # needs Python 3.10+
```

103 classes, 2,925 members, 4,907 `pj*` constants. Generated from
MicrosoftDocs/VBA-Docs, the repository Microsoft's published VBA reference pages
are built from — so no member name is typed by hand. It covers the
**documented** API; a type library also carries hidden members, which is why
`Project.NewTasksAreManual` is an explicit exception in the builder.

## probe/ — ask a real MS Project a question

You do **not** need to run these. They exist for one situation: the analyser
flags a member you know works. That means the model is missing something the
documentation doesn't have, and these settle it.

| | |
|---|---|
| `RS_ModelProbe.bas` | reads every modelled property on a real project and reports what exists. Generated by `make_probe_macro.py` from the model in the submodule. |
| `RS_TypeLibDump.bas` | reads the type LIBRARY instead — what VBA actually compiles against, hidden members included. The better tool of the two. |

Read the header of either before running it. The first version of the probe
called zero-argument methods by accident — `CallByName` with `VbGet` **runs** a
method — which levelled a live schedule and closed MS Project. Both are now
read-only by construction, and `check_vba.py` enforces that the generated probe
names no methods.
